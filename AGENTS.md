# Project Context

Documents (iOS) — original SwiftUI document-hub app for iOS 26, clean-room
implemented (no code, assets, or wording from any third-party application).
Internal codename **DocDeck** (Xcode target, module, and scheme name); the
official app name is **Documents** (`CFBundleDisplayName`). Bundle ID
`com.docdeck.app` must not change — it preserves existing device installs and
their containers.

History note (2026-08-30): this repo was renamed from `oneplus-docs-app`
(local folder and GitHub remote) to `documents-app`. The `analysis/*.md`
planning docs still say "OnePlus Documents" — that names the APK under
analysis, not project branding; do not scrub those references.

## Build & verify

- The `.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen):
  edit `ios/project.yml`, then run `xcodegen generate` from `ios/`.
- Build: `xcodebuild -project DocDeck.xcodeproj -scheme DocDeck -destination 'platform=iOS Simulator,name=iPhone 17 Pro Max' build` (run in `ios/`)
- Unit tests (baseline: all green, 114 tests): same command with `test -only-testing:DocDeckTests`
- Static analysis: `xcodebuild analyze` with the same arguments.

## Constraints

- Only dependency: ZIPFoundation (SPM). Adding packages requires a project-level `.npmrc`-style native-build review only if scripts are involved.
- `.gitignore` artifact patterns are root-anchored (`/tools/`, `/logs/`,
  `/analysis/apk|apktool|jadx/`) because macOS git matches case-insensitively
  and a bare `tools/` once silently excluded `ios/DocDeck/Tools/` from a
  commit. Keep new artifact patterns root-anchored and verify with
  `git check-ignore` before committing directory moves.
- Never commit: `Documents.apk`, `*.mp4`, decompiled APK output, `logs/`,
  `ios/build/`, `.mimosa/`, `.zcode/`.

## Verification discipline

Work is done only after tests are run with real pass/fail output and the full
diff is reviewed. Simulator-green does not validate device-only flows
(scanner, camera) — verify those on hardware.
